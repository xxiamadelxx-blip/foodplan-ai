## Критерии приёмки M2
1. Ровно 150 индивидуальных рецептов, не комбинаторные прототипы: **PASS**.
2. Оригинальный источник для каждого необходимого сырьевого нутриента:
   **PASS по reference 37/37**, не подтверждение готовой еды.
3. Независимый первичный источник технологии каждого блюда: **FAIL 0/150**.
4. Подходящие опубликованные коэффициенты выхода/сохранности либо обоснованная оценка cooked nutrition там, где данные доступны; при отсутствии данных итоговая cooked mass UNKNOWN. **Измерять каждое из 150 блюд не требуется.** Статус реализации новой расчётной модели: **OPEN**.
5. Аллергенные ограничения известных ингредиентов соблюдаются для каждого рецепта; маркировка конкретного магазинного SKU проверяется отдельно и UNKNOWN не принимается за безопасность при аллергии. **SKU-этикетка не обязательное приложение к каждому базовому рецепту.** Реальное покрытие SKU: **OPEN**.
6. Источники независимых опубликованных технологий и автоматизированная повторная проверка вычислений; практический QA выборочно по риску. **Не требовать двух внешних проверяющих на каждое блюдо.** Ссылки на каждый подтверждённый метод и расчёты ещё не оформлены: **OPEN**.

## Протокол каждого последующего цикла
1. Читать этот файл, дорожную карту и последний проверенный SHA.
2. Выбрать ближайший **незакрытый проверяемый** пункт в утверждённом этапе.
3. Не раздувать scope; выполнять только недостающую реализацию.
4. Запустить подходящий тест, собрать независимые доказательства,
   исправить при FAIL, не более 3 попыток одной проблемы.
5. Обновить эту таблицу, дать ссылки на SHA/лог и оставшийся блокер.
6. При полном PASS сразу перейти к следующему M. При BLOCKED перейти
   к независимой задаче, сохранив этап открытым.
