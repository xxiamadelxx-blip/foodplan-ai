# Ingredient → Recipe network (граф рецептур), 21.10.2026

**Владелец требования:** «ниточка от продуктов; две ниточки ведут к одному рецепту → более высокий кандидат к рекомендации».

## Модель

Двудольный ориентируемый в обе стороны индекс:

`Продукт/ingredientId → ingredientToRecipeLinks[] → Рецепт/recipeId`.

Каждое ребро содержит `recipeId`, `ingredientId` и граммы, необходимые для одного приготовления. Рёбра создаются из **реального списка ингредиентов рецепта**, а не из названия блюда, тегов, SKU магазина или ответа нейросети. Дубли одного ингредиента агрегируются в одно ребро, чтобы не накручивать рейтинг.

Рассматриваются продукты в доме (граммы остатков) или набор товаров из уже запланированного недельного списка. Товар магазина должен быть **подтверждённо сопоставлен с canonical ingredientId**; нельзя называть совпадением произвольную карточку с похожим названием.

Пример:
- Есть куриное филе 200 г → связь с рецептом «курица с рисом» (1 полное ребро).
- Есть ещё рис 100 г → 2 полных ребра, рецепт получает дополнительный бонус.
- Есть всего 20 г курицы при требуемых 200 г → **частичное совпадение**, не засчитываем полное ребро. UI может показывать недостающие 180 г.
- Соль/масло/чеснок не должны самостоятельно выталкивать полноценные рецепты на вершину; в существующем каталоге меньшие веса имеют масло и чеснок.

## Реализация и очки

- `IngredientRecipeNetwork.kt`: динамический индекс из текущего каталога, `linksFromProduct(id)`, `matches(availableGrams)`, `scoreBonuses`.
- Полные связи с обычными ингредиентами: первая **+12**, вторая суммарно **+32**, третья **+52**, до **+60**. Каждая полная вспомогательная связь (масло, чеснок) **+2**. Нет доступных граммов → нет связи.
- `RecipeRanker.rank(..., ingredientNetworkBonus=...)`: бонус применяется **только после** обязательной проверки аллергенов/исключений, диеты, кухонного оборудования, времени, известности состава. Теги вкусов, разнообразие и повторяемость продолжают влиять на результат.
- `SevenDayPlanner.plan(..., pantryGrams)`: продвигает разрешённые блюда из имеющихся дома продуктов.
- `MealReplacement.alternatives(...)`: рекомендует замены, использующие больше ингредиентов из текущей недельной внутренней корзины; после фактической замены вся неделя и закупки пересчитываются.
- `ConnectedRecipeSuggestions.recommend(...)`: предоставляет интерфейсу отсортированные подсказки с `linkedProducts`, `missingProducts`, `partiallyAvailableProducts`, общим `score`.
- Детерминированные результаты при одинаковых данных; сортировка равных кандидатов по `recipeId`.

## Границы достоверности

Граф **не утверждает**, что блюда независимым образом проверены, что товары уже куплены или доступны по цене, либо что рецепт безопасен при аллергии. Одна и та же упаковка не может физически удовлетворить любое число одновременно приготовленных блюд: после формирования полного меню `ShoppingAggregation` снова суммирует граммы, а корзина рассчитывает целые упаковки.

При неизвестной маркировке конкретного SKU запрещено выдавать продукт за аллерген-безопасный. Баллы графа не перевешивают жёсткие запреты.

## Приёмка

- [x] Индекс ингредиент → несколько рецептов; граммы и один уникальный канал на ingredientId.
- [x] Два подтверждённых полноценных продукта повышают оценку над одним.
- [x] Частичные количества показаны, но не считаются полным совпадением.
- [x] Аллергия, исключённый продукт, режим питания и оборудование имеют приоритет над графом.
- [x] Подключение бонуса к недельному подбору и замене блюда; отдельный API подсказок.
- [x] Тесты на связи, приоритет, дубли, остатки, запреты записаны в исходники.
- [ ] **CI на точном SHA**: JVM/JUnit + Android APK + эмулятор.
- [ ] Интерфейс: видимое объяснение «2 ингредиента уже есть», список недостающих граммов и переход в рецепт.
- [ ] Интеграция с подтверждёнными реальными SKU выбранного магазина; unknown SKU не становится продуктом в графе.
- [ ] Независимая содержательная приёмка рецептов по критериям M2 ≥150, отдельно от технического графа.
