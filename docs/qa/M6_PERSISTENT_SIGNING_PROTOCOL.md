# M6 · постоянная подпись Android APK: инженерный контракт

**Статус: ИНФРАСТРУКТУРА ПОДГОТОВЛЕНА / РЕАЛЬНЫЙ ПОДПИСАННЫЙ APK НЕ ПРОВЕРЕН.**
Последнее обновление: 2026-10-23. Публичный релиз всё ещё заблокирован
M2 (0/150 независимо принятых рецептов), незавершённым M3/M4 и физическим M5.

## Назначение

Сертификат подписи **должен оставаться одним и тем же** во всех
последующих production обновлениях `com.foodplan.ai`. Временная
подпись GitHub Actions от запуска к запуску делает бесшовные обновления
невозможными. Приватный ключ нельзя коммитить в репозиторий и
прикладывать в публичные отчёты.

**Подписанный внутренний тестовый кандидат ≠ разрешение публично
выпустить приложение.** В проекте не предусмотрена автоматическая
публикация в Play Market, GitHub Releases или магазины APK.

## Реализованная инфраструктура

- `android/app/build.gradle.kts` использует релизную подпись **только**
  при наличии всех четырёх защищённых переменных окружения; частичный
  комплект переменных вызывает FAIL. Обычные PR строят прежний **unsigned**
  release без доступа к ключам.
- `.github/workflows/m6-signed-internal-qa.yml` доступен исключительно
  для ручного `workflow_dispatch` **из `main`**, использует GitHub
  Environment `foodplan-signing`. Он не принимает внешние PR,
  не публикует APK как готовый продукт и очищает временную копию keystore.
- `tools/m6_signed_internal_gate.py` независимо проверяет:
  `com.foodplan.ai`, versionCode, AndroidManifest/classes.dex,
  `aapt` release без флага debuggable, `apksigner verify`,
  **единственный signer** и его SHA-256 certificate fingerprint,
  совпадающий с заранее закреплённым секретным значением. Иначе FAIL.
- `tools/test_m6_signed_internal_gate.py` проверяет отказ при
  неожиданном ключе, повреждённой подписи, отсутствии pinned fingerprint
  и debuggable APK. Эти тесты выполняются в публично безопасном
  `m6-unsigned-release-candidate.yml` без ключей.

## Однократное обеспечение владельцем ключа, не с телефона локально

Только после выпуска M2/M3/M4/M5 и аудита исходников:
нужно сгенерировать и безопасно сохранить **один постоянный JKS ключ**.
Допустима облачная среда GitHub Codespaces с JDK/keytool или
защищённая машина. Пароль/ключ НЕ присылать в чат, issue или PR.
Сделать резервную копию JKS и паролей отдельно от репозитория.

В защищённых GitHub Actions Secrets (или environment
`foodplan-signing`) однократно задать:

| Секрет | Содержание |
|---|---|
| `FOODPLAN_RELEASE_KEYSTORE_BASE64` | base64 содержимого постоянного JKS файла |
| `FOODPLAN_RELEASE_STORE_PASSWORD` | пароль JKS |
| `FOODPLAN_RELEASE_KEY_ALIAS` | alias постоянного ключа |
| `FOODPLAN_RELEASE_KEY_PASSWORD` | пароль ключа |
| `FOODPLAN_RELEASE_CERT_SHA256` | проверенный SHA-256 fingerprint сертификата, вычисленный независимо через `keytool -list -v` |

Никогда не загружать keystore и пароли в `CONTEXT.md`, GitHub
артефакты, тестовые JSON или лог ошибок. Секреты заполняются **один раз**,
затем workflow повторно использует тот же сертификат.

После переноса и проверки кода в `main` вручную запускать workflow
с выбранной `main`. Если любого секрета нет, работа должна
завершаться `BLOCKED`, **не создавая альтернативный ключ на лету**.
Результат с валидной подписью маркируется только
`m6-SIGNED-INTERNAL-QA-NOT-PUBLIC-RELEASE`.

## Важное ограничение обновлений Android

Обычные debug APK из GitHub CI подписываются стандартным **debug**
сертификатом runner; отдельный production JKS будет иметь **другую**
подпись. Android не разрешает обновление уже установленного приложения
с тем же package name, но другим подписантом, даже если versionCode
больше. Установку debug → production нельзя объявлять обновлением
без потери данных: потребуются явный экспорт/перенос либо другое
доказанное решение с сохранением локальных данных. Не требовать
удалить текущую установку и не обещать сохранение недели при смене
подписи без отдельного Gauntlet.
