# FoodPlan AI: независимые критерии выпуска (RELEASE GATE)

**Нельзя предоставлять пользователю промежуточный APK как готовое приложение.** Отдельные успешные GitHub Actions подтверждают только проверяемые части.

## Статусы
- M0: ACCEPTED (репозиторий и архитектура).
- M1: ACCEPTED для анкеты/DataStore и эмулятора, но отдельный force-stop/relaunch тест ещё не закрыт.
- M2: IN PROGRESS, 25 опросных карточек в приложении, 200 программно собранных комбинаций/прототипов; **НЕ 150 подтверждённых рецептов**. Состав и КБЖУ пока оценочные.
- M3: IN PROGRESS, недельное меню и расчётная оценка калорий/БЖУ в JVM/UI. Нет независимой нутриционной приёмки и безопасного диетологического ревью.
- M4: IN PROGRESS, реальный каталог Магнита читается в экспериментальном WebView, предложения сопоставляются с ингредиентами, очередь покупательских SKU открывается на сайте и может нажимать «В корзину». **Содержимое магазинной корзины и точные количества ещё не верифицированы**, а для остальных сетей адаптеры не готовы.
- M5: IN PROGRESS, шаги приготовления и пересчёт недельной корзины при замене блюда; нет полной UX-проверки реальных пользовательских сценариев.
- M6: NOT ACCEPTED, необходимы независимые сквозные QA, безопасность аллергенов и корректное получение цен, подписанная release APK.

## Чек-лист выпуска
1. Не менее 150 **независимо проверенных** рецептов, с технологией, сырой/готовой массой, правильной граммовкой и пищевой ценностью из прослеживаемого источника. Простое комбинаторное размножение шаблонов не считается.
2. Аллергенные синонимы нормализованы, неизвестные компоненты блокируют рекомендации, отдельная обработка риска следов аллергенов. Любой тест провала безопасности блокирует релиз.
3. Для взрослых тестируются 7 дней с необходимым количеством приёмов, адекватными порциями и строгими ограничениями; для несовершеннолетних/особых случаев не предоставлять сомнительные автоматические планы.
4. Продуктовые цены в рублях имеют магазин, регион, время, упаковку и верифицируемый источник. При отсутствии данных статус `budgetVerified=false`, подтверждение бюджета запрещено.
5. Замена, домашние остатки, сохранение, пересчёт общей корзины, перенос в новую неделю имеют независимые контрольные расчёты.
6. Android GUI тест в эмуляторе, принудительная остановка/перезапуск с сохранением данных, повторные тесты после исправлений (Gauntlet).
7. Только после выполнения 1–6: подписанная release APK, версии и release-notes, инструкции установки.

## Эталонные QA проверки
- H1: аллергия на арахис и одобренная пользователем арахисовая еда → исключить из всех кандидатов.
- H2: неизвестный аллерген или неполный состав → не выдать меню как безопасное.
- D1: веганский профиль → исключить рыбу, мясо и молочную продукцию.
- E1: кухонный инструмент отсутствует → рецепт исключён.
- C1: 900-г упаковка при потребности 950 г → 2 упаковки.
- C2: общий остаток 300 г вычтен один раз из недельной потребности 1200 г → к покупке 900 г.
- C3: цены для Москвы нельзя автоматически признать ценами Санкт-Петербурга.
- C4: ручные цены не становятся `verifiedShopPrices=true`, даже если заполнены все позиции.
- C5: после замены блюда суточные КБЖУ и вся корзина пересчитаны.
- P1: save/open/force-stop/start/profile state не пропадает.

Текущий код демонстрирует путь от анкеты до предварительной корзины и **не удовлетворяет всему этому gate**.

## Главный продуктовый инвариант: настоящая корзина магазина

FoodPlan AI должен превращать недельное меню в **корзину конкретного выбранного магазина**, а не только в список граммов. Идеальный результат: один переход в магазин, правильные SKU и количества, пользователь проверяет итоговую цену/адрес/доставку и сам подтверждает оплату.

### M4 acceptance contract (невыполненные пункты блокируют релиз)

- [x] Превратить потребность ингредиента в реальные упаковки одного SKU и пересчитать сумму.
- [x] Отказать при неполном каталоге/устаревшей цене, не изображать отсутствующие товары бесплатными.
- [x] Прочитать карточки публичного сайта Магнита после выбора адреса пользователем.
- [x] Предложить совпадения по ингредиенту и полной стоимости упаковок.
- [x] Передать пользователя по очереди на страницы подготовленных SKU Магнита; попытка клика по официальной кнопке «В корзину» только по явному действию пользователя, без оплаты.
- [ ] Автоматически установить **точное количество** упаковок каждого SKU без ручного изменения счётчика.
- [ ] Независимо прочесть **фактическое состояние магазинной корзины**, сравнить SKU, количество, наличие, доставку, цену с планом.
- [ ] Полностью автоматическая сборка: 10+ позиций за одну команду, тест с авторизованным пользователем в реальном магазине доставки.
- [ ] При изменении меню или подмене товара корректно обновить магазинную корзину (без дублей).
- [ ] Пройти реальные проверки минимум для выбранных пользователем сетей, начиная с Магнита и затем Пятёрочки/Перекрёстка. Каждый адаптер свой, не угадывать незадокументированные API.
- [ ] Скриншоты, подтверждающие фактическую собранную корзину в магазине, и журналы PASS/FAIL после самостоятельной повторной проверки.

Никакой промежуточный APK не выдавать за конечный результат, даже если для модулей есть успешный CI. Покупка/оплата всегда требуют окончательного явного действия человека.
