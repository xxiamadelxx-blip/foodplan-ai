# FoodPlan AI: критерии пользовательского релиза

**Основной выход:** персональный недельный рацион и собственная продуктовая корзина внутри FoodPlan AI. Магазин предоставляет данные, но FoodPlan не заполняет магазинную корзину.

## Релизный контракт, уточнённый 22.10.2026

- **Не требовать адрес доставки/магазина:** нужны ориентировочные цены по российской торговой сети, а не подтверждение остатков конкретного филиала и кассового чека. Отсутствие адреса **не блокирует** ценовую оценку.
- Отделять цену от пищевой безопасности: состав, аллергены, масса и эквивалентность конкретного SKU не подтверждаются самим наличием ценника.
- Из [MILESTONES.md](../../MILESTONES.md): живой независимый прогон Магнита [#66](https://github.com/xxiamadelxx-blip/foodplan-ai/actions/runs/39829467497) дал **31/33** SKU и подытог **7 836,78 ₽**, но полная стоимость **UNKNOWN** из-за `egg` и `oil`. Недоказанные штуки яиц/миллилитры масла не конвертировать в граммы произвольно.
- M2 по-прежнему **BLOCKED 0/150** независимо проверенных приготовленных рецептов. M3/M4 не приняты полностью, M5 без физического cold-restart, M6 unsigned APK не распространять как релиз.
- Пострелизные P0/P1/P2 из [backlog](../POST_RELEASE_BACKLOG.md) не являются дополнительными обязательными M-этапами. Требования фиксируются в [CONTEXT.md](../../CONTEXT.md).

## Точное управление бюджетом и деградация при нехватке денег

- [x] Реализован ползунок 100–100 000 ₽ (непрерывный) и поле точного ввода, принимающее нестандартные целые значения: 100, 356, 63 218, 100 000.
- [x] Частичный набор ограничивается полной стоимостью имеющихся упаковок; при отсутствии подтверждённой/введённой цены не создаёт поддельную покупку.
- [x] Для частичного набора вычисляется предварительное КБЖУ и **разрыв по энергии относительно расчётного ориентира**. Энергетический эквивалент дней не интерпретируется как достаточность рациона.
- [x] Отдельная блокировка при неизвестных аллергенах или отсутствии проверенной маркировки сохраняется и при минимальном бюджете.
- [ ] Независимая проверка качества оптимизации крайне маленьких корзин по реальным ассортиментам и ценам российских магазинов, включая дни без полноценного питания.

## Функциональная приёмка
- [x] Профиль, бюджет и 25 вкусов; локальное хранение на устройстве.
- [x] 200 комбинированных прототипов блюд для тестирования расчётов.
- [x] Экспериментальный сбор видимых цен и отзывов Магнита в WebView.
- [x] Домашние запасы, фасовки, недельная агрегация.
- [x] Движок: выбрать SKU по полной цене упаковок и достоверным оценкам, соблюдая общий лимит, не заставляя расходовать бюджет.
- [x] Черновой алгоритм: попытка заменить дорогие блюда более доступными; богатый бюджет разрешает больше разнообразия при фактическом покрытии ценами.
- [x] Два разных бюджетных сценария 2 500 ₽ и 25 000 ₽ в синтетических unit-тестах.
- [ ] 150 независимо проверенных рецептов с нутриентами, сырой/готовой массой, источниками, валидной обработкой аллергенов.
- [ ] Подключённые магазины покрывают большую часть продуктов типовой недельной корзины.
- [ ] Живой тест **ориентировочных цен сети без адреса**: официальные публичные карточки, дата наблюдения, достоверные фасовки и единицы измерения; непроверенные цены UNKNOWN. Рейтинг/число отзывов показывать только если действительно получены, не делать их обязательными для ценового ориентира.
- [ ] Сквозной тест двух бюджетов **на реальных ценах и рецептах**: дешёвый рацион остаётся достаточным и разнообразным, богатый использует полезные улучшения, ни один не нарушает бюджет.
- [ ] Алгоритм не делает медицинских выводов на основании примерного КБЖУ.
- [ ] Никакого сайта покупок/наполнения корзины: весь список сохраняется и редактируется в приложении.
- [ ] Тесты Android и физического устройства, QA сохранения/рестарта, ошибки сети, недоступность магазина, проверка недублирования покупок.
- [ ] Release APK и независимо проверенный воспроизводимый сценарий.

## Независимые критерии PASS/FAIL
- B01: для синтетических одинаковых SKU при бюджете 2 500 выбрать доступный комплект; при 25 000 разрешить более качественные альтернативы, но не заведомо хуже оценённые ради траты денег.
- B02: дорогой магазинный вариант не выбран только из-за высокой цены; 25 000 ₽ не обязательно полностью потрачены.
- B03: неполные или устаревшие цены → статус бюджет неизвестен, а не PASS.
- B04: ориентировочная цена сети не доказывает наличие в конкретном филиале; неизвестный остаток явно помечается, а подтверждённое отсутствие товара не выдаётся за доступность для покупки.
- B05: реальные рейтинги/количество отзывов используются только если доступны и проверены; отсутствие отзывов не означает плохой продукт и не блокирует показ ориентировочной цены.
- B06: при бюджетной нехватке разрешаются только безопасные замены с сопоставимой калорийностью; если решения нет, возвращается «сверх бюджета», а не фиктивная экономия.
- B07: обновление недельного меню обязательно меняет весь внутренний список продуктов и суммы.
- B08: никаких интеграций с кассой/чекаутом в конечном приложении.

**Текущий результат:** инженерный прототип. До выполнения неотмеченных пунктов НЕ выпускать APK как готовый продукт.
