### P0-TASTE-02 · Иллюстрация на КАЖДОЙ вкусовой карточке

**Уточнение пользователя:** картинки относятся именно к **опросу вкусовых предпочтений**, а не обязательно к выбору «всеядный/веган» в настройках.

**Требование:** фотография или аккуратная иллюстрация *конкретного примера блюда*, понятное название, четыре ответа: «Нравится», «Нейтрально», «Не нравится», «Не пробовал». Иллюстрации локально в APK; текст обязателен и доступен экранному диктору, карточка работает без интернета, на мобильных экранах текст/кнопки не скрываются.

**Критерии приёмки:**
- [ ] 25/25 изображений с корректным отображением и правами использования/собственным авторством, fallback при повреждённом ресурсе.
- [ ] Нет обязательных сетевых/AI-запросов на экране теста.
- [ ] Читаемо при системном увеличении шрифта, поддержан TalkBack/контентное описание.
- [ ] Нажатие ответа сохраняет соответствующий ID в DataStore; полное прохождение 25 карточек и повторное открытие не стирают прежние данные. Android emulator PASS.

### P0-HOME-01 · Домашнее меню вместо обязательной ресторанной недели

**Требование:** отдельная характеристика **бытовой привычности блюда**, независимая от степени усилий/длительности. Обычный режим отдаёт приоритет кашам, простым гарнирам с белком, супам, котлетам, тушёным/запечённым блюдам, простой пасте, салатам и повторному использованию доступных продуктов. Том-ям, рамен, дорогие морепродукты и многокомпонентные блюда не должны регулярно навязываться.

**Предлагаемые настройки:** «Простая домашняя», «Иногда необычная», «Люблю экспериментировать»; по умолчанию «Простая домашняя». Предел «до 1–2 сложных блюд в неделю» является **проектной гипотезой**, только при наличии совместимых рецептов. Нельзя ради лимита нарушать диету, аллергию или делать меню пустым.

**Критерии приёмки:**
- [ ] Детерминированное ранжирование использует время, количество стадий/посуды, редкость ингредиентов и пользовательскую привычность; не использует ИИ.
- [ ] Для одинакового профиля обычная неделя не состоит преимущественно из экзотических блюд; если выбор ограничен аллергией/диетой, предупреждение честное.
- [ ] Настройка влияет на реальные предложения, но **оценка вкуса ≠ приказ приготовить**.
- [ ] Unit и эмуляторные сценарии PASS; продукты и семейные порции пересчитываются.

### P0-PACKS-01 · Количество упаковок крупнее граммов

**ЧАСТИЧНЫЙ PASS В РАБОЧЕМ PR #3:** подтверждённые магазинные упаковки крупнее расчётных граммов. При отсутствии настоящего SKU фасовка и цена явно неизвестны, число пачек больше не берётся из справочной массы ингредиента. Android 48/48 + ADB cold-restart PASS на [CI #39949084176](https://github.com/xxiamadelxx-blip/foodplan-ai/actions/runs/39949084176). Полнота магазинных SKU и разные бюджеты ещё не приняты.

**Требование:** в основном списке покупок сверху **покупательская единица**, а не расчётные граммы.

Пример *только при подтверждённом SKU*: «Куриное филе · **1 лоток по 1 кг** · ~380 ₽», ниже второстепенно «нужно по рецептам 860 г». Аналогично «Рис · **2 пачки по 800 г**» / «Яйца · **10 шт.**» / «Молоко · **1 бутылка, 1 л**». Примеры не являются текущими реальными ценами/фасовками.

**Критерии приёмки:**
- [ ] На узком экране основная строка содержит «сколько купить», фасовку/штуки и известную примерную цену; граммы только вторично/в раскрытии.
- [ ] Считать только **целые пачки**. Разные фасовки корректно суммируются; домашние запасы не создают лишнюю упаковку.
- [ ] Если количество/фасовка не подтверждены: «Фасовка уточняется», «Цена неизвестна», а не «1 упаковка» наугад.
- [ ] Неполная сумма = UNKNOWN, известный подытог выводится отдельно; тесты для 100/356/63218/100000 ₽.

**Требование:** сырьевые названия нутриентных справочников остаются внутри доменного ядра. Пользователь **никогда** не видит «куриное яйцо, съедобная часть». То же для «сухой вес», «выход готового продукта», единиц массы/объёма, которые не должны выглядеть как название еды.
