# FoodPlan AI: окончательный пользовательский сценарий

Версия 2026-10-21. **UX CONTRACT / AUTHORITATIVE**. Этот документ главнее экспериментальных M2/M4 экранов и прототипов.

## Первый запуск: один раз

1. Пользователь вводит пол, возраст, рост, вес, физическую активность.
2. Выбирает цель: похудение / сушка с ограничениями безопасности / поддержание / набор.
3. Выбирает тип питания (всеядный, вегетарианский, веганский, пескетарианский), **отдельно** аллергены, нежелательные продукты и другие ограничения. Не смешивать аллергию с «не люблю».
4. Выбирает кухонную технику и количество человек. Указывает предпочтительное число приёмов пищи и время приготовления.
5. Оценивает 25 примеров блюд («люблю», «нормально», «не люблю», «не пробовал»).
6. Сохраняем профиль и результаты опроса локально. При повторном открытии приложения **никакого повторного onboarding**.

Бюджет на неделю, город/магазин выбираются уже при **использовании**, на экране «Продукты». Профиль и пищевые предпочтения редактируются позднее через «Настройки». Если цен/магазина нет, не придумывать итог и не показывать ложную готовую корзину.

## Обычное пользование: только ТРИ раздела

### Продукты

- Выбор города/магазина и **точного бюджета 100..100000 ₽ шаг 1 ₽**.
- «Собрать список на неделю»; список обычных продуктов/конкретных упаковок: название, сколько купить, цена (если известна), сумма на неделю и честная пометка отсутствующих данных.
- Система сама внутри: недельный рацион → обезличенная потребность → парсер выбранного магазина → нормализация SKU → состав, производитель, сорт, цена, размер упаковки → детерминированные фильтры, эквивалентность и целые упаковки → общая корзина. Не выводить внутренний процесс в UI.
- При 100 ₽ или любой недостаточной сумме показать возможную **частичную** корзину с предупреждением, а не 7 дней полноценного питания.
- Список пересчитывается при смене блюда, числа дней приготовления, числа человек и бюджета. Изменение магазина не означает подтверждённого наличия.
- Не отправлять заказ и не управлять корзиной магазина.

### Рецепты

- Открыть один из **7 дней**, выбрать завтрак/обед/ужин (или другие приёмы при настроенном числе приёмов).
- Блюдо: название, ингредиенты с граммовками, число порций, КБЖУ с пометкой оценки, время, пошаговое приготовление.
- Для **конкретного блюда** выбрать степень усилий (FAST / INVOLVED / ALL_OUT); запрос «Другое блюдо» учитывает те же ограничения, вкусы и продукты.
- «Готовить на N дней»: выбранный рецепт занимает одноимённый приём пищи на N последовательных дней без удвоения ингредиентов; суммарная закупка равна N порциям, умноженным на число человек. Не заполнять дни за пределами недели; не выдавать хранение приготовленной еды за автоматически безопасное.
- После замены/пакетной готовки **сразу** пересчитать меню, граммовки и общую покупку; повторные блюда показывать честно.
- Пользователь **не** видит граф ингредиентов, поисковый индекс, SKU-анализ, M2/M4, «тестовый каталог» как отдельную функцию.

### Настройки

- Личные параметры, цель, питание/аллергии/исключения, техника, число человек, вкусовой тест (можно пересмотреть), параметры времени.
- Без обязательной повторной регистрации/анкетирования. Изменения применяются ко всему плану.

## Скрытые внутренние подсистемы

Парсер российских магазинов, граф «продукт→рецепт», scoring, нутриентная проверка, производитель/состав, SKU-эквивалентность, бюджетная оптимизация, Gauntlet, источники и отчёты: **только внутренняя механика**. Допустимы краткие человекопонятные пояснения («Этот товар дешевле при том же подтверждённом составе», «Цена неизвестна»), но не техническая диагностика.

## Приёмка пользовательского UX

- [ ] Onboarding выполняется однократно в последовательности параметров → цель → диета/аллергии → техника/семья → вкусы.
- [ ] После onboarding сразу открывается обычный экран; повторный запуск не открывает анкету.
- [ ] Во время использования доступны только «Продукты», «Рецепты», «Настройки»; внутренние графы/SKU/парсинг не являются отдельными вкладками.
- [ ] В продуктах доступны бюджет и выбранный магазин, недельные граммы, цены/UNKNOWN.
- [ ] В рецептах есть день, завтрак/обед/ужин, запрос замены, выбор усилий для конкретного блюда и длительность готовки N дней.
- [ ] При готовке на N дней недельная корзина учитывает ровно N порций × число человек, без двойного списания.
- [ ] Аллергии и ограничения невозможно обойти ни усилием, ни заменой, ни бюджетом.
- [ ] JVM tests, APK, Android emulator E2E, PASS/FAIL по exact SHA.

UX контракт не заменяет отдельные M2 ≥150 проверенных рецептов и M4 реальный магазинный парсер. Все недостоверные данные честно помечаются, но не становятся пользовательскими техническими экранами.
