# FoodPlan AI: окончательный пользовательский сценарий

Версия 2026-10-21. **UX CONTRACT / AUTHORITATIVE**. Этот документ главнее экспериментальных M2/M4 экранов и прототипов.

## Уточнение 23.10.2026: интернет-каталог работает ВНУТРИ Android

После выбора магазина, бюджета и сборки недельного плана FoodPlan **сам** использует встроенный парсер публичных страниц по известным путям каталогов магазина и соответствующим официальным SKU. Android-приложение читает видимые цены и фасовки онлайн, сопоставляет их с реальными потребностями текущей недели, сохраняет проверенные ценовые предложения в локальном DataStore, пересчитывает количество целых упаковок и стоимость. Пользователю не требуется открывать отдельный браузер, вручную нажимать «считать каждый продукт» или полагаться на то, что ИИ/помощник каждый раз вручную составит корзину. GitHub Actions лишь тестирует этот рабочий механизм, не обслуживает повседневного пользователя.

В рамках текущего М4 автоматический парсер с подтверждёнными URL реализуется для **Магнита**; у ВкусВилла действует отдельный автоматический поиск названий без подтверждённых цен, остальные сети требуют собственных проверяемых адаптеров. Нельзя изображать поддержку всех 11 магазинов без реальных источников. В отсутствие интернета, отказе сайта или неясной фасовке цена **UNKNOWN**, офлайн-список и рецепты остаются доступны. Яйца/масло не переводятся из штук/мл в съедобные граммы без независимого источника. Подтверждённая цена не доказывает аллергенную безопасность или наличие товара.

**Критерий приёмки:** на устройстве выбор «Магнит» и готовая неделя автоматически запускают чтение онлайн, данные попадают в обычный «Продукты», замена блюд меняет расчёт нужных продуктов, сохранение работает после повторного открытия, запрещённых API и обхода защиты сайта нет. Реальное прохождение через эмулятор/доступный источник проверять отдельно от фиктивных тестовых HTML. Код в рабочем PR ≠ публичный релиз.

## Первый запуск: один раз

1. Пользователь вводит пол, возраст, рост, вес, физическую активность.
2. Выбирает цель: похудение / сушка с ограничениями безопасности / поддержание / набор.
3. Выбирает тип питания (всеядный, вегетарианский, веганский, пескетарианский), **отдельно** аллергены, нежелательные продукты и другие ограничения. Не смешивать аллергию с «не люблю».
4. Выбирает кухонную технику и количество человек. Указывает предпочтительное число приёмов пищи и время приготовления.
5. Оценивает 25 примеров блюд («люблю», «нормально», «не люблю», «не пробовал»).
6. Сохраняем профиль и результаты опроса локально. При повторном открытии приложения **никакого повторного onboarding**.

Бюджет на неделю, город/магазин выбираются уже при **использовании**, на экране «Продукты». Профиль и пищевые предпочтения редактируются позднее через «Настройки». Если цен/магазина нет, не придумывать итог и не показывать ложную готовую корзину.

### Уточнения к UX от 22.10.2026 (записаны, не реализованы)

**Опрос вкусов.** Речь о **25 карточках с примерами блюд**, а не о выборе медицинских/диетических ограничений. К каждой карточке нужна картинка реального примера блюда и текстовое название. Стартовые примеры преимущественно знакомые домашние блюда, а не том-ям, рамен, паста с креветками и другая малоизвестная ресторанная еда. Сохраняются четыре ответа «Нравится / Нейтрально / Не нравится / Не пробовал»; «Не пробовал» не уменьшает рейтинг других вкусов. Детальный пересмотр набора и критерии: [POST_RELEASE_BACKLOG.md](POST_RELEASE_BACKLOG.md), P0-TASTE-01/02.

**Продуктовая корзина.** Пользователь читает прежде всего **сколько целых пачек/лотков/бутылок/штук купить**, затем ориентировочную цену, и только после этого расчётные граммы. Не показывать «куриное яйцо, съедобная часть» в любом пользовательском тексте: это внутреннее описание нутриентного эталона; представлять как «Яйца, N шт.» только при подтверждённом количестве. Отсутствующая фасовка/цена остаётся UNKNOWN. Критерии: P0-PACKS-01/P0-LABELS-01.

**Меню.** Повседневная неделя ориентирована на простую домашнюю еду; нравится блюдо в анкете ≠ готовить его каждую неделю. Сложные блюда допустимы по отдельному желанию и ограничениями, но не должны навязываться. Критерии: P0-HOME-01.

**Сохранение.** Пользователь сообщил, что список сохраняется после обычного закрытия/повторного открытия. Не считать этот сценарий сломанным. Тест физического `force-stop → cold-relaunch` остаётся отдельно непроверенным.

**Статус:** решения закреплены в [CONTEXT.md](../CONTEXT.md). Они внесены в пострелизный backlog без молчаливого добавления новых обязательных M-этапов. Не ставить новым UX-задачам PASS до реализации и испытаний.


## Обычное пользование: только ТРИ раздела

### Продукты

- Выбор города/магазина и **точного бюджета 100..100000 ₽ шаг 1 ₽**.
- «Собрать список на неделю»; список обычных продуктов/конкретных упаковок: название, сколько купить, цена (если известна), сумма на неделю и честная пометка отсутствующих данных.
- Система сама внутри: недельный рацион → обезличенная потребность → парсер выбранного магазина → нормализация SKU → состав, производитель, сорт, цена, размер упаковки → детерминированные фильтры, эквивалентность и целые упаковки → общая корзина. Не выводить внутренний процесс в UI.
- При 100 ₽ или любой недостаточной сумме показать возможную **частичную** корзину с предупреждением, а не 7 дней полноценного питания.
- Список пересчитывается при смене блюда, числа дней приготовления, числа человек и бюджета. Изменение магазина не означает подтверждённого наличия.
- Не отправлять заказ и не управлять корзиной магазина.

### Рецепты

- Открыть один из **7 дней**, выбрать завтрак/обед/ужин (или другие приёмы при настроенном числе приёмов).
- Блюдо: название, ингредиенты с граммовками, число порций, КБЖУ с пометкой оценки, время, пошаговое приготовление.
- Для **конкретного блюда** выбрать степень усилий (FAST / INVOLVED / ALL_OUT); запрос «Другое блюдо» учитывает те же ограничения, вкусы и продукты.
- «Готовить на N дней»: выбранный рецепт занимает одноимённый приём пищи на N последовательных дней без удвоения ингредиентов; суммарная закупка равна N порциям, умноженным на число человек. Не заполнять дни за пределами недели; не выдавать хранение приготовленной еды за автоматически безопасное.
- После замены/пакетной готовки **сразу** пересчитать меню, граммовки и общую покупку; повторные блюда показывать честно.
- Пользователь **не** видит граф ингредиентов, поисковый индекс, SKU-анализ, M2/M4, «тестовый каталог» как отдельную функцию.

### Настройки

- Личные параметры, цель, питание/аллергии/исключения, техника, число человек, вкусовой тест (можно пересмотреть), параметры времени.
- Без обязательной повторной регистрации/анкетирования. Изменения применяются ко всему плану.

## Скрытые внутренние подсистемы

Парсер российских магазинов, граф «продукт→рецепт», scoring, нутриентная проверка, производитель/состав, SKU-эквивалентность, бюджетная оптимизация, Gauntlet, источники и отчёты: **только внутренняя механика**. Допустимы краткие человекопонятные пояснения («Этот товар дешевле при том же подтверждённом составе», «Цена неизвестна»), но не техническая диагностика.

## Уточнение 23.10.2026 · Встроенный парсер и корзина без ручного участия

**Авторитетное требование пользователя:** после выбора конкретного магазина и бюджета Android-приложение **самостоятельно** читает публичные карточки/каталоги именно выбранной сети по заранее проверенным путям, когда это позволяет источник; никаких ручных действий ChatGPT и разовых CLI-сканирований для пользовательской корзины. Это работающий в Android Kotlin-компонент, не фоновый сервис с ИИ и не внешний платный API.

- В памяти приложения и в DataStore сохраняются только наблюдённые реальные цены и массы упаковок вместе с источником, магазином, временем и сроком годности наблюдения. В APK встроены **пути**, а не цены.
- При замене блюда, увеличении числа дней или порций, выборе другого бюджета список продуктов и целые упаковки пересчитываются **сразу локально**, без нового скачивания той же карточки только потому, что изменились требуемые граммы.
- Если новый рецепт добавил ингредиент, его известный публичный путь должен быть проверен автоматически; недоступный источник не блокирует 7 дней/21 блюдо и список покупок.
- При отсутствии настоящего парсера для конкретной выбранной сети запрещено использовать товары/цены другого магазина. Для неё цена остаётся **UNKNOWN**; магазинный адаптер реализуется отдельно, после подтверждения официальных разрешённых публичных маршрутов.
- Физические граммы, штуки, миллилитры и масса продукта после снятия кожуры/слива жидкости не взаимозаменяемы. Цена коробки яиц и бутылки масла может быть показана без объявления полной суммы недели.
- CI тестирует всю связь **встроенный Android parser → retailer observation → persisted offers → 7-дневный shopping UI → пересчёт без повторного GET**, а внешний сетевой пробник лишь подтверждает доступность источника. Это независимые виды доказательств.

## 24.10.2026 · Режим замены рецепта из товаров уже составленной недели

В «Рецепты» пользователь нажимает блюдо → «Другое блюдо». Внутри существующего окна сначала видны **продукты текущей недели** (обычные названия для покупателей), затем карточки альтернатив, использующих уже запланированные товары. Для варианта показаны: имя блюда, совпавшие продукты, новые товарные категории, позиции с увеличившейся потребностью, доступность бюджета **только при полноте подтверждённых цен**. Это прогноз корзины по **всем 7 дням** и выбранной длительности готовки, не отдельная оценка одной тарелки.

Выбор альтернативы выполняет уже имеющийся `RecipeBatchPlanner.apply` и сохраняет неделю через `SavedWeekPlanner`; исходный набор не меняется от просмотра. Жёсткие запреты пищи, аллергенов и кухонной техники действуют **до** рекомендаций. Неизвестные следы аллергенов магазинных SKU не объявляются безопасными. Дополнительной вкладки «Конструктор» не появляется, API платных ИИ не используются. Алгоритмические критерии и статус проверок: [RECIPE_CONSTRUCTOR_CONTRACT.md](RECIPE_CONSTRUCTOR_CONTRACT.md), [MILESTONES.md](../MILESTONES.md).
