# FoodPlan · двухрежимный детерминированный конструктор рецептов

**Решение пользователя от 24.10.2026.** Не отдельный четвёртый экран и не генеративный ИИ. Алгоритм скрыт за экранами «Продукты» и «Рецепты». Опирается на уже созданные воспроизводимые домашние технологии и их ингредиентные связи, не сочиняет новые недостоверные способы готовки.

## Режим A: собрать неделю из профиля

`FoodProfile` (цель/порции/число приёмов/семья, диета, аллергены, нелюбимые продукты, оборудование, время/усилие), оценки `TasteSurvey`, бюджет 100–100000 ₽, магазин, домашние остатки → **сначала жёсткая фильтрация**, затем вкус/частота повторов/КБЖУ/наличие уже нужных ингредиентов → 7 дней → единая агрегированная корзина с вычетом запасов **один раз**, а не для каждого блюда.

С доступными настоящими предложениями выбранного магазина `BudgetWeekRefiner` может адаптировать меню только из допустимых замен и фактически известных сумм. Цена для неподтверждённого товара **UNKNOWN**, не 0 ₽ и не «уложились». Если бюджет не обеспечивает рацион, показывать отсутствие доказанной доступности/питательной достаточности, но не придумывать продукты. Изменение магазина/цены пересчитывает покупательские упаковки без ИИ.

## Режим B: заменить конкретный рецепт *из списка продуктов*

Пользователь открывает день → завтрак/обед/ужин → «Другое блюдо». Сверху **читаемый текущий список продуктов**, ниже совместимые альтернативы, составленные из проверяемых шаблонов рецептов:
1. Диета, аллергенная маркировка, нелюбимые продукты, ограничения приготовления и кухонная техника фильтруются **до** любой оценки вкуса/экономии. При аллергии без известного состава и следов выбранных SKU подмена закрыта, как и первичная неделя.
2. Для каждого допустимого блюда вычисляется **пробная вся неделя** с тем же количеством дней готовки/людей, без изменения сохранённого выбора, затем новая закупка. Сравнить её с исходной корзиной: какие продукты остаются в прежнем списке; что добавится впервые; какие существующие позиции нужны в большем количестве; что удалится. Продукт, уже присутствующий в покупках, не значит что его хватает без докупки.
3. Приоритет рекомендаций: сначала варианты **без новых товарных категорий**, дальше минимум новых категорий/увеличения количеств, затем число связей с **отмеченными пользователем** продуктами, явно отмеченные ♥ любимые блюда, вкусовая анкета и устойчивый порядок. Все эти мягкие предпочтения действуют **только после** жёсткой фильтрации. Если отмечены продукты, в каждом предлагаемом блюде должен быть хотя бы один из них; если выбранная комбинация не даёт подходящих блюд, честно показывать пустой результат. Не показывать «дешевле», если нет полного подтверждённого ценового набора.
4. Замена всегда применяет стандартные ограничения `RecipeBatchPlanner.apply`, пересчитывает все 7 дней и список, обновляет локальное сохранение. При отказе сохранённая неделя не меняется.
5. Сердечки любимых рецептов сохранять отдельно от недельного меню в `ProfileStore`/DataStore; они должны переживать закрытие приложения, загрузку нового профиля и «Начать новую неделю», не превращая рецепт в аллерген-безопасный. Показывать выбор продуктов и любимые рецепты именно в боевом `FoodPlanHomeScreen`, без новых вкладок.

## Исправление выбора домашних продуктов · 2026-10-27

**Релизный дефект второго режима:** изначально `selectedIngredientIds` пересекались только с `current.shopping`. Когда товар уже был дома и его остаток исключил позицию из недельной покупки, явный выбор такого продукта давал пустые рекомендации даже при наличии допустимых рецептов. В результате «Из продуктов» фактически означало «Только из планируемых покупок».

**Контракт после исправления:** если пользователь явно отметил известные ингредиенты, проверять связь рецепта именно с ними, независимо от текущей потребности в докупке. Если выбор пуст, по умолчанию использовать продукты из недельной корзины. Сортировать явный выбор по числу совпавших ингредиентов в самом кандидате, а не только по совпадениям с исходными покупками. UI предлагает и положительный домашний запас, и недостающие в нём продукты из покупок; товары только из запаса помечаются «дома». Реальные `ShoppingAggregation` и бюджет остаются рассчитанными после пробной замены всей недели; наличие товара дома не делает любую будущую покупку бесплатной.

## Важные ограничения

- На экране пользователя только продукты, рецепты и настройки. Никаких новых технических разделов графа/парсера/этапов.
- Существующая сеть «продукт → рецепт» остаётся индексом поддержки; алгоритм может пользоваться 150 авторскими рецептами и 200 прототипами, но **не** выдаёт прототип за подтверждённое внешними источниками блюдо. Статус M2 остаётся OPEN до документарной проверки источников 150 рецептов.
- Никаких ключей LLM и внешнего API для составления рациона; StubEngine пригоден только для отдельного мокирования сетевого адаптера и в данном офлайновом алгоритме **не используется**.
- Модуль не обещает медицинскую полноценность питания по приблизительным нутриентам и не подтверждает аллергенную безопасность самой магазинной упаковки.

## Проверка

JVM: диета/аллергия/нелюбимые; одинаковые входные данные дают стабильный порядок; замена с тем же количеством дней/семьёй; исправление корзины после замены; сначала товары из списка, но честное указание роста количества; нехватка подтверждённых цен остаётся UNKNOWN; исходная неделя не меняется при просмотре вариантов. Android UI: в «Рецепты → Другое блюдо» показываются продукты, варианты и изменения покупок; после сохранения пересчитана корзина; три вкладки остаются прежними. Gauntlet отдельный на точном SHA.


## Invariant: edits must respect the entire current profile

A saved 7-day week is not automatically safe under later edits to the user's diet, prohibited ingredients, or household details. Replacement validates the **entire updated week**, not just the newly proposed dish; if a retained meal is now excluded, the replace/apply operation returns a user-readable blocked result and asks to rebuild the week. Invalid profile inputs, minors or negative home-stock quantities cannot crash the replacement planner. This hard condition precedes updated grocery aggregation and can never be bypassed by favorites, taste ranking, graph links or budget.
