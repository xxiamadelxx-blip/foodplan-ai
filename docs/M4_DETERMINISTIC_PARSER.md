# M4: детерминированный поиск и сравнение продуктов (без ИИ)

## Контракт
Выбранный пользователем магазин обслуживается отдельным разрешённым адаптером. Поиск запускается только по действию пользователя; авторизация, регион и выбранный адрес сохраняются в штатной сессии магазина (если сайт это разрешает). В запросы отправляются **только названия продуктов**: имя, заболевания, рост, вес, вкус, размер бюджета, личные сведения и весь рацион в поисковую форму магазина не передаются.

### Конвейер
1. `ShoppingAggregation.fromDays`: по 7 дням суммировать ингредиенты, один раз вычесть остатки дома.
2. `AnonymousRetailPlanner.build`: для каждого конкретного продукта сформировать одно или несколько общих русскоязычных наименований; «овощи» не подменяют конкретную морковь/брокколи. Первая очередь: куриное **филе**, затем **длиннозерный рис**.
3. Адаптер выбранного магазина открывает разрешённый пользовательский поиск/категорию. Если требуется CAPTCHA, сайт не отвечает или форма не найдена, вернуть `BLOCKED/UNKNOWN`. Обход антибота, скрытых API и платных ИИ не допускается.
4. Перечитать видимые SKU и ссылки. Дедупликация по канонической ссылке/артикулу. Не считать первые 12 SKU полным ассортиментом, пока не пройдены все страницы.
5. Для каждого подходящего кандидата прочитать **конкретную карточку**: производитель, состав, вид/сорт/обработка, масса, цена, URL, время и адрес. Недоступное поле = `UNKNOWN`, не выдумывать.
6. Отфильтровать физически другой товар, блюдо, несопоставимую часть животного, иной сорт или обработку, товар не в наличии, просроченную цену, неясную фасовку и чужой адрес. Аллергии относятся к отдельному **жёсткому** фильтру этикетки.
7. Сравнить только взаимозаменяемые по опубликованным атрибутам позиции. Рассчитать цену за 1 кг **и** реальную стоимость целых упаковок на неделю. Отзывы и бренд не являются доказательством качества; дорогой товар не получает автоматическую надбавку к оценке.
8. Выдать результат `COMPARABLE`, `NEEDS_PRODUCT_DETAILS`, `REJECTED` или `NO_OFFERS`, причины и ссылки. Пропуски остаются пропусками. Цена сайта никогда не считается ценой чека или доказательством наличия.

## Обязательные фильтры
| Порядок | Проверка | Правило |
|---|---|---|
| F01 | URL/магазин/регион | Точный HTTPS-хост, поддерживаемый адаптер, выбор адреса пользователем |
| F02 | Дата/остаток | <=6 часов, не `OUT_OF_STOCK`; неизвестный остаток не превращать в `IN_STOCK` |
| F03 | Базовая идентичность | Куриному филе не подменять бедро, тушку, маринованную/готовую курицу |
| F04 | Форма продукта | Сухой длиннозерный шлифованный рис не подменять варёным, пропаренным или круглозёрным |
| F05 | Фасовка/нетто | Масса, количество упаковок, мультипак. Весовые и фасованные товары не смешивать без точного типа ценового предложения |
| F06 | Источник состава | Состав **конкретного SKU**, изготовитель, реальная ссылка. Не переносить состав соседнего бренда |
| F07 | Аллергены | Без проверенной этикетки нельзя объявлять товар безопасным при аллергии, включая следы |
| F08 | Сравнимость | Одинаковый вид, обработка и нормализованный состав; другой бренд допускается, другие характеристики нет |
| F09 | Экономика | Учитывать полные цены упаковок и весь недельный спрос, а не скидку и цену одной порции |
| F10 | Ограничения | Без платного ИИ, обхода защиты, навязанной покупки или приписывания недостающих данных |

## Пример 120 ₽ против 400 ₽
Два пакета одинаковой массы с **проверенным** составом «рис шлифованный» и той же разновидностью «белый длиннозерный» могут попасть в одну группу. Тогда предпочтение 120 ₽ обосновано **экономически**, но не означает, что их вкусовые, лабораторные показатели и происхождение идентичны. Если у одного нет состава, сорта, производителя или подходящей массы, вывод «то же самое» **запрещён**.

## Жёсткая приёмка
- `CI`: сборка `:domain:test`, `:app:assembleDebug`, Android instrumented tests PASS на SHA PR.
- `LIVE`: для выбранного магазина на Android пользователь подтверждает свой реальный адрес; считываются все 7-дневные позиции по списку, в отчёте есть полный список найденных и пропущенных, SKU URL/артикул, цена, время, данные происхождения, причины отказа.
- `COMPLETENESS`: ни одного `UNKNOWN` не маркировать как успешную закупку/полностью подтверждённую неделю; ограничение 12 SKU не представлять как полный рынок.
- `NEGATIVE`: бедро вместо филе, пропаренный вместо обычного риса, состав без производителя, просроченная/чужая цена, весовой товар с фиктивной упаковкой, запретные аллергены и разные фасовки обязательно FAIL.
- `INDEPENDENCE`: сверить 20 неповторяющихся реальных SKU и не менее двух сравнений дешёвого/дорогого с официальными страницами и сохранёнными артефактами; повторить на реальной Android-сессии.
- `SAFETY`: аллергии требуют отдельного источника маркировки; неизвестно = запрет утверждать безопасность. Никаких платных AI API и интернет-запросов с персональной анкетой.

**M4 NOT ACCEPTED**, пока эти критерии не пройдены. **M2 0/150** независимо проверенных рецептов, этот модуль M4 не подменяет их приёмку.
